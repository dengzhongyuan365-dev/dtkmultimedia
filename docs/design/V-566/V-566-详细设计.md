## 1. 当前 Issue 的目标、范围和非目标

### 1.1 目标

为 dtkmultimedia 源码包新增独立共享库 `libdtk6tablerecognizer`，实现"图片 → 表格"的完整本地离线识别流程：输入含表格的 `QImage`，识别表格结构（行、列、合并单元格）与每个单元格文字，输出 HTML、Excel（`.xlsx`）及结构化单元格数据（`QList<DTableCell>`）。本设计仅覆盖库本身，不含截图工具入口集成与主程序跳转。

### 1.2 范围

- 新增公开头文件 `include/dtktablerecognizer/`（5 个头文件）
- 新增内部模块 `src/tablerecognizer/`（8 个模块 + CMakeLists + models/）
- 构建集成：`src/CMakeLists.txt` 追加一行、`misc/` 新增 3 个模板、`debian/` 追加包定义与 2 个 `.install` 文件
- 测试：`tests/` 新增 7 个单元测试 + `examples/` 新增 `tablerecognizerCmd` 冒烟示例（仅 Debug）

### 1.3 非目标

- 不含截图工具入口集成：不在 deepin-screen-recorder 工具栏增加"表格识别"按钮
- 不含贴图（pin）程序集成
- 不含主程序跳转/交互设计
- 不含在线/云端识别
- 不含对扫描件/PDF 等非截图场景的专门优化
- 不修改 `libdtk6ocr`、`libdtk6multimedia`、`libdtk6multimediawidgets` 任何源码

## 4. 详细交互、状态流转或时序

### 4.1 主识别流程时序

```
调用方 → DTableRecognizer::recognizeAsync(QImage, timeout)
  └─[工作线程] DTableRecognizer::runPipeline(imageCopy, deadline)
     │
     ├─ 阶段1：TableStructureDetector::detect(imageCopy)
     │    └─ OrtInferenceEngine::run(SLANet_plus.onnx, preprocessedTensor)
     │         → 原始输出张量 → 结构 token 解码 → QList<DetectedCell>{row,col,rowSpan,colSpan,bbox}
     │    [超时检查] 超时 → 返回 success=false
     │
     ├─ 阶段2：DtkOcrWrapper::recognize(imageCopy)
     │    └─ DOcr.loadPlugin("PPOCR_V5") → setImage(QImage) → analyze()
     │         → textBoxes() / resultFromBox(i) → QList<OcrTextBox>{bbox, text}
     │    [超时检查] 超时 → 返回 success=false
     │
     ├─ 阶段3：CellTextMapper::map(cells, ocrBoxes)
     │    └─ center-point 归入 + IoU 兜底 + 从左到右/从上到下拼接 → cells[i].text 填充
     │    [超时检查]
     │
     ├─ 阶段4：HtmlTableBuilder::build(cells) → html
     ├─ 阶段5：XlsxTableBuilder::build(cells, xlsxPath) → 实际 .xlsx 路径
     │
     └─ 组装 DTableResult{success=true, html, xlsxPath, cells, source="SLANet_plus", errorMessage=""}
  └─ emit recognitionDone(DTableResult)   // 回到调用方线程
```

### 4.2 降级流程

```
阶段1 主路径 ORT 推理失败 / 模型加载失败 / 置信度过低
  ↓
尝试降级：Img2TableFallback::detect(imageCopy)
  └─ OpenCV 形态学/霍夫检测表格线 → QList<DetectedCell>（仅有线表格有效）
  ↓ 成功
阶段2/3/4/5 重复（OCR + 映射 + HTML/Excel）
  → DTableResult{source="img2table"}
  ↓ 降级仍失败
DTableResult{success=false, errorMessage="未识别到表格"/具体错误}
```

降级触发条件：
- ORT 运行时不可用（`OrtInferenceEngine::loadModel` 失败）
- SLANet 模型加载失败
- 无线表格检测置信度过低
- ORT 推理抛异常

降级路径仅对有线表格有效，无线表格在降级路径中返回失败。

### 4.3 线程模型与状态流转

```
DTableRecognizer 内部状态：
  Idle ──recognizeAsync──→ Running ──正常完成/超时/异常──→ Idle
                              │
                              └─（recognitionDone 信号发出后回到 Idle）
```

- `recognizeAsync` 使用 `QtConcurrent::run` 或 `QThread` worker 执行管线。
- QImage 跨线程深拷贝（`image.copy()`），确保图像数据线程安全。
- `QTimer` 超时控制：超时在各阶段间隙检查（ORT 推理中途不可中断，超时为尽力而为，实际超时可能略大于设定值）。
- 超时/异常均置 `success=false`，附带 `errorMessage` 说明。
- `recognitionDone` 信号通过 `QueuedConnection` 回到调用方线程。

### 4.4 超时语义

- 默认超时 10 秒，可由调用方通过 `recognizeAsync` 的 `timeout` 参数调整。
- 超时在阶段切换间隙检查，无法中断 ORT 推理中途。
- 超时按失败处理，返回 `success=false`，`errorMessage` 含"超时"说明。

## 5. 数据模型、持久化、迁移、兼容性

### 5.1 数据模型

#### DTableCell（公开）

```cpp
struct DTableCell {
    int row, col;        // 单元格逻辑行列位置（0-based）
    int rowSpan, colSpan; // 跨行/跨列数（默认 1）
    QRectF bbox;          // 单元格在原图中的物理包围盒
    QString text;         // 单元格内识别的文字（OCR 填充）
};
```

#### DTableResult（公开）

```cpp
struct DTableResult {
    bool success;          // 识别是否成功
    QString html;          // HTML 表格文本
    QString xlsxPath;      // Excel 文件路径（成功时有效）
    QList<DTableCell> cells; // 结构化单元格列表
    QString source;        // "SLANet_plus" 或 "img2table"
    QString errorMessage;  // 失败时的错误说明
};
```

#### 内部数据结构

```cpp
// TableStructureDetector 输出
struct DetectedCell { int row=0, col=0, rowSpan=1, colSpan=1; QRectF bbox; };

// DtkOcrWrapper 输出
struct OcrTextBox { QRectF bbox; QString text; };
```

### 5.2 持久化

- **Excel 输出**：`XlsxTableBuilder::build(cells, outPath)` 写入 `.xlsx` 文件。`outPath` 为空时写入临时目录（`QDir::tempPath()`），返回实际路径。
- **HTML 输出**：纯内存字符串，不落盘，由调用方决定如何保存。
- **模型文件**：SLANet_plus ONNX 安装到 `/usr/share/libdtk6tablerecognizer/models/`，Debug 构建时通过 `-DTABLEREC_MODEL_DIR=...` 指向源码目录。
- **无数据库**：库不使用任何数据库，无状态持久化需求。

### 5.3 迁移

不适用及原因：本库为全新增量新增，无既有数据需迁移。

### 5.4 兼容性

- **源码兼容**：纯增量新增，不修改任何现有库源码、公开 API 或行为。
- **构建兼容**：仅追加 `add_subdirectory` 一行，不影响既有库编译。
- **ABI 兼容**：新库为独立 `.so`，`VERSION/SOVERSION` 跟随 `CMAKE_PROJECT_VERSION`，不影响既有库 ABI。
- **打包兼容**：新增独立二进制包，不影响既有包。
- **运行时兼容**：新库为可选依赖，未安装不影响既有库运行。
- **API 稳定性**：首次交付为 v1 契约，语义改变时递增版本。

## 6. 接口契约（输入、输出、错误、版本兼容）

### 6.1 公开 API 契约

```cpp
// dtablerecognizer_global.h
#define D_TABLERECOGNIZER_BEGIN_NAMESPACE namespace Dtk::TableRecognizer {
#define D_TABLERECOGNIZER_END_NAMESPACE }
#define D_TABLERECOGNIZER_EXPORT // Q_DECL_EXPORT/IMPORT

// dtablecell.h
struct DTableCell {
    int row, col, rowSpan, colSpan;
    QRectF bbox;
    QString text;
};

// dtableresult.h
struct DTableResult {
    bool success;
    QString html;
    QString xlsxPath;
    QList<DTableCell> cells;
    QString source;
    QString errorMessage;
};

// dtablerecognizer.h
class D_TABLERECOGNIZER_EXPORT DTableRecognizer : public QObject {
    Q_OBJECT
public:
    explicit DTableRecognizer(QObject *parent = nullptr);
    ~DTableRecognizer();
    void setXlsxOutputPath(const QString &path);  // 缺省=临时目录自动生成
    void recognizeAsync(const QImage &image,
                        std::chrono::milliseconds timeout = std::chrono::seconds(10));
signals:
    void recognitionDone(const DTableResult &result);
};
```

### 6.2 输入

| 参数 | 类型 | 约束 |
|------|------|------|
| `image` | `const QImage &` | 含表格的图片；跨线程深拷贝；空/无效图片返回失败 |
| `timeout` | `std::chrono::milliseconds` | 默认 10s；超时按失败处理 |
| `path`（setter） | `const QString &` | xlsx 输出路径；空则写临时文件 |

### 6.3 输出

| 字段 | 成功时 | 失败时 |
|------|--------|--------|
| `success` | `true` | `false` |
| `html` | HTML 表格文本 | 空字符串 |
| `xlsxPath` | 实际 `.xlsx` 路径 | 空字符串 |
| `cells` | 结构化单元格列表 | 空列表 |
| `source` | `"SLANet_plus"` 或 `"img2table"` | 空字符串 |
| `errorMessage` | 空字符串 | 错误说明（超时/无表格/降级失败等） |

### 6.4 错误码与错误说明

| 场景 | `success` | `errorMessage` 示例 | `source` |
|------|-----------|---------------------|----------|
| 正常识别成功 | true | "" | "SLANet_plus" |
| 降级识别成功 | true | "" | "img2table" |
| 图片无效/空 | false | "输入图片无效" | "" |
| 超时 | false | "识别超时" | "" |
| 无表格 | false | "未识别到表格" | "" |
| ORT 加载失败 + 降级失败 | false | "模型加载失败：<详情>" | "" |
| 降级失败 | false | "降级识别失败：<详情>" | "" |

### 6.5 版本兼容

- 公开 API 首次版本为 v1。
- 语义改变时递增版本（`v1 → v2`），通过头文件版本宏标识。
- `.so` 的 `VERSION`/`SOVERSION` 跟随 `CMAKE_PROJECT_VERSION`。

## 7. 异常、边界条件、降级与回滚

### 7.1 异常处理

| 异常场景 | 处理方式 |
|----------|---------|
| ORT 推理抛异常 | 捕获，尝试降级路径 |
| DOcr::analyze() 失败 | 捕获，`success=false`，记录错误 |
| libxlsxwriter 写入失败 | `xlsxPath` 置空，`success=false`，`errorMessage` 说明 |
| QImage 跨线程访问 | 进入工作线程前 `image.copy()` 深拷贝 |
| 模型文件缺失 | `OrtInferenceEngine::loadModel` 返回 false，触发降级 |

### 7.2 边界条件

| 边界条件 | 处理方式 |
|----------|---------|
| 图片中无表格 | 主路径 + 降级均无结构 → `success=false`，"未识别到表格"，不产出空表格 |
| 图片过小/过暗 | 检测置信度过低 → 触发降级 → 降级失败 → 返回失败 |
| 表格结构严重不规则 | 结构检测置信度低 → 降级或失败 |
| 合并单元格跨多行多列 | `rowSpan`/`colSpan` 正确编码，HTML/Excel 正确输出 |
| OCR 框跨多个单元格 | IoU 兜底，按最大重叠归入 |
| 同一单元格多个 OCR 框 | 从左到右、从上到下拼接 |
| 空单元格（无文字） | `text` 置空字符串，不省略单元格 |
| 超时 | 阶段间隙检查，返回失败 |

### 7.3 降级

降级链（详见 §4.2）：
1. SLANet_plus(ORT) + dtk6ocr(PP-OCRv5) — 主路径
2. img2table(OpenCV 有线表格) + dtk6ocr(PP-OCRv5) — 降级路径
3. 返回失败（仅 errorMessage，无 UI）

### 7.4 回滚

本库为纯增量新增，回滚仅需：
1. 从 `src/CMakeLists.txt` 移除 `add_subdirectory(tablerecognizer)`
2. 撤销 `debian/control.in` 中的新包定义与 Build-Depends
3. 删除新增的 `debian/libdtk6tablerecognizer*.install`
4. 删除 `src/tablerecognizer/`、`include/dtktablerecognizer/`、`misc/dtk6tablerecognizer*.in`

不影响既有库构建与运行。

- **0.4 OrtInferenceEngine PoC**：用 ONNX Runtime C++ API 加载 `SLANet_plus.onnx`，对样本图推理并 dump 原始输出张量。
- **0.5 前后处理 C++ 移植**：移植 SLANet 预处理（resize/归一化）与后处理（结构 token 解码 → 单元格 bbox），与 Python 参考实现逐张比对。
- **0.6 引入客观基准**：引入 PubTabNet TEDS + 真实截图样本，记录基线指标，向 PM 提议 D1 阈值（如 TEDS ≥ 0.85）。

### 8.2 Phase 1 — 模块开发（1.5–2 周，按依赖顺序）

模块接口签名（内部命名空间 `Dtk::TableRecognizer`，内部模块可用匿名/内部命名空间）：

**1) OrtInferenceEngine（叶子，依赖 onnxruntime）**
```cpp
class OrtInferenceEngine {
public:
    bool loadModel(const QString &modelPath);
    bool isLoaded() const;
    std::vector<std::vector<float>> run(const std::vector<float> &input,
                                        const std::vector<int64_t> &inputShape);
    QString lastError() const;
};
```

**2) TableStructureDetector（依赖 OrtInferenceEngine）**
```cpp
struct DetectedCell { int row=0, col=0, rowSpan=1, colSpan=1; QRectF bbox; };
class TableStructureDetector {
public:
    explicit TableStructureDetector(OrtInferenceEngine *engine);
    bool detect(const QImage &image, QList<DetectedCell> &cells, QString &error);
    bool available() const;
};
```

**3) DtkOcrWrapper（叶子，依赖 libdtk6ocr）**
```cpp
struct OcrTextBox { QRectF bbox; QString text; };
class DtkOcrWrapper {
public:
    bool initialize();   // loadPlugin("PPOCR_V5")
    bool recognize(const QImage &image, QList<OcrTextBox> &boxes, QString &error);
    bool available() const;
private:
    Dtk::Ocr::DOcr m_ocr;
    bool m_loaded = false;
};
```
实现要点：`DOcr::textBoxes()` 返回 `QList<TextBox>`，`TextBox.points`（`QList<QPointF>`）取包围盒得 `bbox`；`resultFromBox(i)` 取文本。须在工作线程调用（`analyze()` 同步阻塞）。

**4) CellTextMapper（叶子，纯逻辑）**
```cpp
class CellTextMapper {
public:
    void map(QList<DetectedCell> &cells, const QList<OcrTextBox> &ocrBoxes);
};
```
算法：OCR 框中心点落入单元格 bbox 即归入；多框同单元格按从左到右、从上到下拼接；IoU 兜底处理跨格/边界框。

**5) HtmlTableBuilder（叶子，纯逻辑）**
```cpp
class HtmlTableBuilder {
public:
    static QString build(const QList<DTableCell> &cells);
};
```
输出 `<table>`，按 row/col 排序，`rowSpan`/`colSpan` 写入对应属性，文本做 HTML 转义。

**6) XlsxTableBuilder（叶子，依赖 libxlsxwriter）**
```cpp
class XlsxTableBuilder {
public:
    static QString build(const QList<DTableCell> &cells, const QString &outPath);
};
```
按 `(row, col)` 写入单元格，合并区域用 `worksheet_merge_range`。`outPath` 为空时写入临时目录并返回实际路径。

**7) Img2TableFallback（叶子，依赖 opencv_mobile）**
```cpp
class Img2TableFallback {
public:
    bool detect(const QImage &image, QList<DetectedCell> &cells, QString &error);
    bool available() const;
};
```
用 OpenCV 形态学/霍夫检测表格线，仅对有线表格有效；无线表格返回失败。

**8) DTableRecognizer 门面（依赖以上全部）**
```cpp
class D_TABLERECOGNIZER_EXPORT DTableRecognizer : public QObject {
    Q_OBJECT
public:
    explicit DTableRecognizer(QObject *parent = nullptr);
    ~DTableRecognizer();
    void setXlsxOutputPath(const QString &path);
    void recognizeAsync(const QImage &image,
                        std::chrono::milliseconds timeout = std::chrono::seconds(10));
signals:
    void recognitionDone(const DTableResult &result);
};
```
实现要点：`QtConcurrent::run` 或 `QThread` worker 执行管线；`QTimer` 超时控制；超时在各阶段间隙检查；QImage 跨线程深拷贝；主路径失败自动走降级路径。

## 10. 风险、待确认事项和变更记录

### 10.1 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| xlsx 输出路径缺口 | 概要设计公开 API 未含 xlsx 路径入参，本设计以 `setXlsxOutputPath()` setter 填补 | 待 PM/设计确认此细化是否符合预期 |
| 测试二进制依赖新增 | 将 tablerecognizer 源码纳入 `tests` glob 后，测试二进制需 onnxruntime/xlsxwriter 才能链接 | CI 测试镜像须预装，或可选化处理（`find_package` 可选 + stub 隔离） |
| 超时粒度 | ORT 推理中途无法中断，超时只能在阶段间隙生效，实际超时可能略大于设定值 | 设计中明确"尽力而为"语义，文档说明 |
| 新依赖三架构打包 | `libonnxruntime-dev`、`libxlsxwriter-dev` 在 arm64/x86_64/loong64 的就绪性是 loong64 交付关键路径 | 前置阻断项 1/2 在 Phase 0 验证 |
| D1 精度阈值未定 | 现有精度数据来自程序化自定义样本，无线表格"达标"需客观基准 | Phase 0 引入 PubTabNet TEDS 后由 PM 钉死阈值 |
| 模型体积 | SLANet_plus ONNX ~7.4MB 随包分发，增加包体积 | 待 PM 确认可接受 |
| OCR V5 运行环境 | 若目标 UOS 的 dtk6ocr 包未随附 V5 模型，数字识别准确度下降 | 前置阻断项 3 在 Phase 0 确认 |

### 10.2 前置阻断项（需在 Phase 0 前确认）

1. **ORT loong64 编译验证**：ONNX Runtime 源码含 loongarch64 MLAS 优化，需确认 UOS loong64 上可编译产出可用 `.so`。
2. **SLANet_plus 权重法务 spot-check**：核验模型卡 license 与 `_plus` 数据 provenance，确认按 Apache-2.0 标注合规。
3. **dtk6ocr PP-OCRv5 目标环境可用性**：确认目标 UOS 运行环境的 dtk6ocr 包已随附 V5 模型。

### 10.3 待确认事项

1. **D1 精度阈值具体数值**：PM 已回复"需求/PM 审核通过"，但未给出 PubTabNet TEDS 最低值与真实截图结构正确率下限的具体数字。建议 Phase 0 引入基准后，由 PM/技术方钉死客观阈值（如 TEDS ≥ 0.85）。
2. **onnxruntime / xlsxwriter 三架构打包就绪性**：需确认 UOS 仓库已提供 `libonnxruntime-dev`、`libxlsxwriter-dev`（arm64/x86_64/loong64）。
3. **dtk6ocr V5 模型随包确认**：需确认目标 UOS 运行环境的 `libdtk6ocr` 包已安装 `dtkocrmodels/v5/`。
4. **xlsx 输出路径 setter 细化**：`setXlsxOutputPath()` 填补公开 API 缺口，缺省写临时文件，不改 `recognizeAsync` 签名。待 PM/设计确认此细化是否符合预期。
5. **降级失败的用户表现**：库在主模型与降级均失败时只返回错误说明、不自带 UI。请 PM 确认是否符合预期。
6. **超时默认值**：默认 10 秒，请 PM 确认是否符合产品体验预期。
7. **后续集成需求跟踪**：截图工具内的表格识别入口明确不在本需求内，请 PM 确认是否另立需求跟踪。
